## 1. Executive Summary

The Person waterfall turns a thin identity hint — a name, an email, a LinkedIn URL — into an enriched `master_person` record, a `Person:Entity` graph node with its work/education/expertise edges, and a projection package the App renders as a person card.

The live call graph is **201 functions** reached from **10 execution roots**. Structurally it is four layers:

| Layer | What it does | Anchor |
| --- | --- | --- |
| **Entry gate** | Normalize input → kill-switch → pre-API dedup → provider cascade → resolve → write rows → dispatch | `master-person-new` #13039 |
| **Orchestrator** | 13 phases (0–12, phase 9 twice) over the resolved person | `enrich-master-person` #13040 |
| **Terminal layer** | Deterministic checkpoint receipts + lease-based retry sweeps that decide when a run may be called finished | `seed-person-terminal-run` #13205, sweep #13260 |
| **Leaf layer** | ~130 record writers, link/social scrapers, graph and storage helpers | `process-enrich-layer` #12615, `create-master-link` #2541 |

Three things dominate the port:

1. **The terminal/receipt layer is the hard part, not the phases.** A person run is not "done" when phase 12 returns — it is done when a seeded checkpoint set is satisfied and the current-company dependency resolves. This layer was built after the last spec-grade audit and is where the recent churn is concentrated.
2. **Two load-bearing default-coercion bugs** (section 20) change queue behavior for explicit `0`. Reproducing them faithfully is arguably wrong; both are flagged as `Open question for Mark`.
3. **The graph MERGE key must change.** Xano MERGEs `Person` on `master_person_id` (an int PK). Universe has no such id — the Go writer must MERGE on `universe.entity.id`. This is the single largest intentional deviation in the port.

## 7. End-to-End Worked Example

### Example A — happy path, new person (Zeno Rocha)

```json
{
  "full_name": "Zeno Rocha",
  "email": ["zeno@resend.com"],
  "profile_url": "https://www.linkedin.com/in/zeno-rocha-6270a914"
}
```

Expected control flow:

1. **#13039** trims/lowers inputs; `name-format` #2649 splits `full_name` → first/middle/last/suffix/nickname.
2. **Kill switch** `check-kill-switch-v2` #4617. Blocked → `log_crash` #542 and return; no person row.
3. **Pre-API local dedup** — `master_link` on normalized LinkedIn URL, then `master_email`, then `master_person` name match.
4. **Provider cascade** `cascade-person-data` #13037: PDL `POST /v5/person/enrich` → Enrich Layer `person-linkedin` / `person-email` → Exa fiber `#13179` → Exa profile `#12738`.
5. **Resolve** `match-master-person` #13038 (also E.164-formats phones via #2540).
6. **New-person branch** — `db.add master_person`, `add-person-node` #2601 (graph), `create-master-link` #2541, `upsert-person-alias` #13187, emails/phones, `link-fundable-person` #12793.
7. **Dispatch** — `enrich-master-person` #13040 **async-shared** (or `upsert-enrich-person` #12854 if `queue` or `cascade_depth > 0`).
8. **#13040** seeds the terminal checkpoint set (#13205) **before phase 7**, runs phases 0→12, then `run-person-orchestrator-terminal` #13207.
9. Root closeout selects a sparse current company → records `person_terminal_company_dependency` #760 → dispatches `enrich-master-company` #12992 at depth 0.
10. **Task #192** (60 s) reclaims the receipt if the async terminal dispatch was lost.

Expected AlloyDB writes:

| Table | Key | Important fields |
| --- | --- | --- |
| `universe.entity` | `id` (uuid) | `entity_type='person'`, `enrichment_state`, `cascade_depth=0`, `graph_node_uuid` |
| `universe.entity_identifier` | `(kind,normalized_value)` where strong | `linkedin` → strong; `email` → strong; `name` → soft |
| `universe.person` | `entity_id` | names, `current_title`, `current_company_id`, `bio`, `avatar_url` |
| `universe.entity_fact` | `(entity_id,field)` where chosen | one row per source per field, `is_chosen` winner |
| `universe.enrichment_payload` | `(entity_id,provider,request_hash)` | raw PDL / EL / Exa envelopes |
| `person_terminal_stage` | `(entity_id, run_id, stage)` | checkpoint receipts |

Expected graph writes:

| Node/Edge | MERGE key | Required properties |
| --- | --- | --- |
| `(:Person:Entity)` | `universe.entity.id` (**was** `master_person_id`) | `uuid`, `created_at`, `updated_at`, `display_label`, `name`, `visibility`, `embeddings` |
| `(p)-[:WORKS_AT]->(c)` | endpoint pair | `created_at` via `coalesce`, `updated_at`, `title`, `weight`, `description` |
| `(p)-[:HAS_EXPERTISE]->(d)` | endpoint pair | `weight` = `min(round(10 + match_score × 160), 50)`; created edges flat `10` |

Acceptance checks:

- Re-running the same input creates **no** second `universe.entity`.
- Re-run leaves graph `created_at` unchanged and moves `updated_at`.
- The person node carries `:Entity` (the shared vector index lives on that base label).

### Example B — explicit-zero regression (the parity trap)

```json
{ "full_name": "Ada Lovelace", "email": ["ada@example.com"], "priority_tier": 0, "queue": true }
```

Live Xano behaviour: #13039 applies `priority_tier|first_notempty:4`, so **tier 0 becomes tier 4**. Task #126 drains only `priority_tier <= 1` — the row never drains. Entering through `upsert-enrich-person` #12854 directly instead applies `first_notnull:4` and **tier 0 survives**.

The fixture must assert whichever behaviour Mark rules correct (section 22, Q1). Do not let a developer pick silently.

### Example C — dedup hit

Same LinkedIn URL, second submission: the pre-API dedup resolves before any provider call, no PDL/EL/Exa spend, `count` on the queue row increments, `priority_tier`/`cascade_depth` take the **better** (lower) of existing vs incoming, and `source_*` fields are backfilled with `first_notempty` only where currently empty.

## 8. Function Contract Sheets

### 8.1 `mvp/get-add/master-person-new` #13039

**Role:** THE entry gate. 2,973 lines, 53 `try_catch` blocks, 6 lambdas, `first_notempty` ×25, `first_notnull` ×0.

**Reads:** `master_person`, `master_link`, `master_email`, `master_phone`, `fundable_people`, `fundable_angel_investments`, `runtime_metadata`.
**Writes:** `master_person`, `person_enrich_data`, `enrich_history_person`, `log_enrichment_person`, `human_review_required`, `log_crash`.
**Calls:** #13037, #13038, #2649, #4617, #12820, #13183, #13187, #2541, #2601, #2784, #2783, #2540, #12793, #12615, #2536, #237, #13036, #12854, #13040.
**Dispatch mode:** `async-shared`.

```go
func MasterPersonNew(ctx context.Context, in GateInput) (GateResult, error) {
    in = normalize(in)                       // trim; lower emails
    name := nameFormat(ctx, in.FullName)     // #2649 LLM split

    if blocked, _ := killSwitch(ctx, in); blocked {
        logCrash(ctx, "kill-switch", in)
        return GateResult{Blocked: true}, nil   // no person row
    }

    // pre-API local dedup, in this order — cheapest and strongest first
    if id, ok := findByNormalizedLinkedIn(ctx, in.Links); ok { return existing(ctx, id, in) }
    if id, ok := findByEmail(ctx, in.Email);            ok { return existing(ctx, id, in) }
    if id, ok := findByNameHints(ctx, name, in);        ok { return existing(ctx, id, in) }

    payloads := cascadePersonData(ctx, in)   // #13037 — PDL → EL → Exa fiber → Exa
    match    := matchMasterPerson(ctx, in, payloads) // #13038

    entity := createPersonEntity(ctx, name, in, match) // universe.entity + universe.person
    writePersonNode(ctx, entity)                       // #2601 equivalent
    upsertAliases(ctx, entity, payloads)               // #13187
    attachLinksEmailsPhones(ctx, entity, in, payloads)
    linkFundable(ctx, entity)                          // #12793

    // PARITY TRAP — see §20 D1. Live Xano coerces an explicit 0 to 4 here.
    tier  := firstNotEmpty(in.PriorityTier, 4)
    depth := firstNotEmpty(in.CascadeDepth, 0)   // benign: default is 0

    if in.Queue || depth > 0 {
        return queueUpsert(ctx, entity, depth, tier, in.DeepResearch)
    }
    go enrichMasterPerson(ctx, entity.ID, in.DeepResearch, depth) // async-shared
    return GateResult{EntityID: entity.ID}, nil
}
```

**Idempotency key:** normalized LinkedIn URL (strong) → email (strong) → name + employer hint (soft, must not be globally unique).
**Failure behaviour:** every stage is individually `try_catch`-wrapped; a failed stage logs to `log_crash` and the gate continues. Only the kill switch returns early.
**Artifact decisions:** the 53 nested try/catch blocks are a Xano control-flow workaround — in Go use one error type per stage plus a stage-result accumulator, not 53 nested recoveries. `Xano artifact — do not reimplement`.

### 8.4 `mvp/enrich/enrich-master-person` #13040

**Role:** the orchestrator. 3,383 lines, `try_catch` ×37, `precondition` ×8, `first_notnull` ×26, `first_notempty` ×7. **v3.85 (2026-07-28).**

**Input:** `master_person_id` plus `deep_research`, `cascade_depth`, `force_run`, `current_company_only`, `allow_investor_network_cascade`.

**Pre-flight:** stale-dispatch guard (person row deleted since the async fire → early return + `log_crash`), then a **60 s source-keyed debounce** on `enrich_history_person` where `source == "Master Person Enrich"`; `force_run: true` bypasses. The setup row is upsert-keyed on `(master_person_id, source)`, so the debounce key is `updated_at`.

```go
func EnrichMasterPerson(ctx context.Context, req EnrichReq) error {
    p, ok := loadPerson(ctx, req.EntityID)
    if !ok { logCrash(ctx, "stale dispatch"); return nil }
    if debouncedWithin(ctx, p, 60*time.Second) && !req.ForceRun { return nil }

    seedTerminalRun(ctx, p)                       // #13205 — BEFORE phase 7

    for _, ph := range []int{0,1,2,3,4} { runPhase(ctx, p, ph) }
    runExaProfile(ctx, p)                         // 4b — #13031
    runPhase(ctx, p, 5)
    runPhase9(ctx, p, WithThesis(false))          // EARLY phase 9
    runPhase(ctx, p, 6)
    chooseBestCurrentRole(ctx, p)                 // #12621
    recordTerminalStage(ctx, p, "pre_phase_7")    // #13203
    runPhase(ctx, p, 7)                           // edge resolvers
    runPhase(ctx, p, 8)                           // expertise
    reverseMusicBridge(ctx, p)                    // 8b, env-gated #13171
    runPhase9(ctx, p, WithThesis(true))           // phase 9 AGAIN
    runPhase(ctx, p, 10)                          // NO-OP STUB — still called
    runPhase(ctx, p, 11); runPhase(ctx, p, 12)

    finalizeSemanticState(ctx, p)                 // #13194 — the success gate
    runOrchestratorTerminal(ctx, p)               // #13207
}
```

Every phase runs in its own `try_catch` writing per-phase `qa_passed` / `CRASH: phase-N` rows to `log_crash` #542 — whose `phase` column is a **strict enum**; writing an unlisted value makes the crash logger itself fail. Failures are logged but never block later phases.

**`Fix in Go`:** phase 10 #12831 is an empty stack (`{}`) still invoked with its own try/catch and qa log. Do not port the call site.

### 8.5 Terminal receipt layer

| Function | ID | Contract |
| --- | :-: | --- |
| `seed-person-terminal-run` | #13205 | Seeds one deterministic checkpoint set per run. Called **before phase 7** so an uncatchable phase-7 death is observable rather than silent. |
| `record-person-terminal-stage` | #13203 | Records a stage transition; sanctions `success → running` for the auxiliary preflight stage. 3 preconditions. |
| `run-person-orchestrator-terminal` | #13207 | Settles the orchestrator barrier immediately after terminal materialization, **before** shared coordination. |

### FullEnrich — the async one that shapes the architecture

`enrich/full-enrich-reverse-email-lookup` #13036 dispatches; FullEnrich calls back into **API #8594** `POST api:8hTTyqsU/webhook/contact-finished`, which:

1. Reads `custom.person_enrich_data_id`, `custom.data_source`, `custom.current_company_only`, `custom.cascade_depth` off each item.
2. **v1.8 safety guard** — refuses any item with empty `custom.data_source`, logging and counting it as `refused_no_data_source`. This exists because a sandbox dispatch with `data_source=""` defaulted to **live** and corrupted a real person's record, then retried 5× because FullEnrich's client timeout is shorter than the 95–180 s processing window.
3. Waits on `enrich_history_person.processing == false` with a 30 s grace and a **30-minute deadline**, then calls `process-full-enrich` #13049 regardless.

<Warning>
  **Go rebuild must not reproduce the wait loop.** A 30-minute synchronous hold inside an HTTP handler is a Xano-shaped workaround for the lack of a durable queue. In Go: ack the webhook immediately, persist the payload, and enqueue the apply step. The **data_source guard is a real invariant** and must be kept. `Xano artifact — do not reimplement` (the wait); `Preserve for parity` (the guard).
</Warning>

## 13. Queue and Worker Contract

### `queue_enrich_person` (#582) worker

**Upsert key:** `master_person_id` → `entity_id`.

**Merge semantics from `upsert-enrich-person` #12854 (live, verbatim):**

- `cascade_depth` ← `$input.cascade_depth|first_notempty:0` then `best_depth = min(existing, incoming)`; existing default when absent is **99**.
- `priority_tier` ← `$input.priority_tier|first_notnull:4` then `best_tier = min(existing, incoming)`; existing default **4**. **`first_notnull` here — explicit 0 survives.**
- `count` ← `existing.count + 1` (existing default 1).
- `source_*` fields backfilled with `first_notempty` — set only where currently empty.

```sql
-- drain: strictly ordered, one row per tick in Xano; batch in Go
SELECT * FROM universe.queue_enrich_person
 WHERE processing = false AND priority_tier <= $1
 ORDER BY priority_tier ASC, cascade_depth ASC, id ASC
 FOR UPDATE SKIP LOCKED
 LIMIT $2;
```

**Failure path (live):** on error the drain writes `log_crash` and resets `processing = false` so the row retries. There is **no attempt cap and no DLQ** — a poison row retries forever. `Fix in Go`: add `attempts` + DLQ.

**Cron state:** Task #126 is `active = false`, gated to `priority_tier <= 1` since 2026-07-03. The queue is drained manually via #12816 or "Run Now". **The frozen contract is "not draining."**

## 14. Graph Node and Edge Contract

### `(:Person:Entity)` — writer `mvp/node/add-person-node` #2601

Live Cypher, reconstructed from the generating lambda:

```cypher
MERGE (p:Person { master_person_id: $master_person_id })
ON CREATE SET
  p.uuid           = randomUUID(),
  p.created_at     = timestamp(),
  p.updated_at     = timestamp(),
  p.display_label  = 'Person',
  p.name           = $name,
  p.name_embedding = vecf32($openai_1536),   -- optional
  p.embeddings     = vecf32($gemini),        -- optional
  p.visibility     = false
ON MATCH SET
  p.updated_at     = timestamp(),
  p.name           = $name,
  p.name_embedding = vecf32($openai_1536),
  p.embeddings     = vecf32($gemini)
SET p:Entity
RETURN p
```

| Aspect | Contract |
| --- | --- |
| MERGE key | `master_person_id` → **must become `universe.entity.id`** in Universe |
| `created_at` | set **only** ON CREATE — stable across re-runs (assert this) |
| `:Entity` | always added; the shared vector index lives on this base label, **not** per-node-type |
| `visibility` | `false` on create |
| Embeddings | Xano dual-writes OpenAI `name_embedding` (1536) + Gemini `embeddings`. **Universe carries Gemini `gemini-embedding-001` (1536, L2-normalized) only** — decision #1. `Fix in Go`: drop `name_embedding`. |
| Retry | 3 attempts, then `log_crash` and abort |

### Edge envelope — `mvp/edges/create-work-edges` #2800

```cypher
MERGE (p)-[r:WORKS_AT]->(c)
SET r.created_at  = coalesce(r.created_at, timestamp()),
    r.updated_at  = timestamp(),
    r.title       = $title,
    r.weight      = $weight,
    r.description = CASE WHEN ... END
```

`coalesce(r.created_at, timestamp())` is the idempotency guarantee — **one shared helper in `internal/graph`**, never hand-written per writer.

<Warning>
  **`mvp/falkor/send-cypher` #2815 returns Cypher errors as strings, not thrown errors.** #2601's `try_catch` retry loop therefore cannot see a Cypher-level failure — it only catches transport errors. A Go client **must** inspect the response and return a real `error`, or graph failures read as silent nulls. `Fix in Go`.
</Warning>

Other conventions carried from the live graph: use `'Label' IN labels(a)` in `WHERE` (FalkorDB rejects `a:Label` there); remove a property by setting it to `NULL` (no `REMOVE`); use parameterized queries so plans cache. Node/edge catalog: [Person Nodes](/guides/enrichment/waterfall/person-nodes) · [Person Edges](/guides/enrichment/waterfall/person-edges) · [person cyphers](/guides/cyphers/person-pipeline).

  **Two known graph gaps carried from the frozen reference** (already documented on the functions page): work-derived `INVESTED_IN` is a dead branch — the classifier hardcodes `isInvestor:false`, so investment edges come only from the deal writers; and **no live writer stamps `:C_Suite`** since #2758 v1.8 dropped the dynamic-label lambda. ## 17. Error Handling and Observability

| Concern | Live behaviour | Go target |
| --- | --- | --- |
| Crash log | `log_crash` #542; `phase` is a **strict enum** — an unlisted value makes the logger itself fail | typed enum in code; unknown → `other`, never a failed write |
| Log semantics | `log_crash` is an **audit log**, not a crash log — it carries success telemetry too | separate `severity`; never infer health from row counts |
| Per-phase | each phase writes `qa_passed` / `CRASH: phase-N` and continues | structured per-phase span + result accumulator |
| Silent death | phase 7 could die uncatchably → `enrich_success=false`, `reason=null`, **zero** crash logs | pre-seeded terminal receipt (#13205) makes it observable — **keep this design** |
| Graph failure | 3 retries then `log_crash`, run continues | same, but Cypher-string errors must become real errors |
| Provider failure | logged, cascade continues to next tier | same; record which tier answered |

## 19. Acceptance Checks

### Contract checks
- Given a `full_name` + `email` with no existing match, the gate returns a new entity id and creates exactly one `universe.entity`.
- A second identical submission returns the **same** entity id and creates no new row.
- Supplying `master_person_id` on #7977 never invokes the gate.
- Kill-switch-blocked input creates **no** person row and writes one `log_crash`.

### Provider replay checks
- With `person-happy-linkedin`, PDL/EL/Exa clients consume recorded payloads and produce identical normalized structs.
- `person-dedup-hit` makes **zero** provider calls.
- Full provider envelopes land in `universe.enrichment_payload.raw`, not just `.data`.

### Graph checks
- Re-run does not duplicate MERGE-keyed nodes or edges.
- `created_at` unchanged on re-run; `updated_at` advances.
- Every person node carries `:Entity`.
- Empty/null optional properties are **absent**, not empty strings.
- A Cypher-level error surfaces as a Go `error`, never a silent null.

### Queue checks
- Duplicate hit increments `count` and takes min tier / min depth.
- Explicit `priority_tier: 0` behaves per Mark's Q1 ruling — asserted, not assumed.
- Worker locks one row via `SKIP LOCKED`; a poison row DLQs after N attempts rather than retrying forever.

### Terminal checks
- A run whose async terminal dispatch is dropped is reclaimed by the sweep within one interval.
- A claimed retry that fails closes through its own lease token, leaving no `running` receipt.
- A company-less person reaches a terminal state.

### Projection checks
- No package is emitted before #13194 equivalent succeeds.
- Re-applying the same `projection_run_id` is a no-op.
- Product-owned dynamic sections are untouched.

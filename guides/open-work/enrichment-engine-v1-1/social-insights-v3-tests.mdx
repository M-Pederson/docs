> **Status: test infrastructure LIVE in Xano; first sandbox run complete 2026-08-14.** Nothing here touches the v1 production path or the v2 experiment. **This page is the changelog of record for the Go/GCP rebuild** — if v3 tests win, every artifact below is the port spec.

## Hypothesis

v2 proved the evidence pool — not the synthesis model — is the quality bottleneck: Exa snippets are mostly undated and can't see inside walled-garden platforms. v3 adds **first-party post capture**: pull the person's actual recent posts (X, LinkedIn, Instagram) into a table, then hand the synthesis model dated, first-party evidence. Expected wins: real quotes, exact dates, measurable posting cadence, platform-migration signals, and post-evidenced interests.

## First test — sandbox Richard Kerris (#9), 2026-08-14

**Posts capture:** X 25 tweets (handle via twitter\_person fallback) \+ LinkedIn 1 post \+ Instagram 0 (no handle) → 26 rows upserted into `social_post`.

**Synthesis (grok-4.6):** 8 insights, \$0.048, 76s, 9,406 prompt tokens (posts lane ≈ \+3k tokens vs v2). Quality jump over v2 is visible in kind, not just degree:

- **Real quotes with exact dates** from his own posts: “game changing” (Omniverse→Vision Pro, 2024-04-09), “Embrace it” (Runway GenAI, 2024-04-06), “Just don’t make me wear the red shirt” (Star Trek humor, 2024-04-02).
- **Cadence \+ platform migration** — impossible from Exa snippets: first-party X shows 8 posts 2024-03→2024-04 then goes quiet; dated professional posting continues on LinkedIn through 2026. One insight states exactly that.
- **Style read from actual posts**: short partner-tagging one-liners (@runwayml, @nvidia, @Apple, @OTOY), emoji, humor.
- **Interests before → after:** `[photography, music]` → `[photography, music, drums, star trek, family]` — drums returned with post evidence, star trek and family are new, all via the append-unique merge.

## Open items

1. **Public-Instagram posts shape untested** — the parser now handles both `items[]` and `data.user.edge_owner_to_timeline_media.edges[]` shapes, but no test person has a public IG yet; verify on a live-datasource person with a public account.
2. **X discovery via Exa is weak** — `includeDomains: x.com` returned 0 candidates for every person tested; x.com is poorly indexed. Handle-reuse guesses \+ the existing twitter\_person fallback carry X coverage for now; consider a ScrapeCreators handle-probe lane (guess → scrape → verify) as the primary X discovery path.\\n3. **LinkedIn depth** — profile payload carried 0–5 posts depending on the run; if more depth is needed, evaluate a dedicated LinkedIn posts endpoint.
3. **Lane distillation** — at 40-post caps, raw posts fit the prompt; for prolific posters add a cheap distiller lane (kimi-k3 at ~\$0.047/31s or deepseek-v4-flash at ~\$0.0007/run) before synthesis.
4. **Refresh policy** — posts refetch cadence \+ `social_post` retention are undecided; current guard is only the insights 5-day freshness check.

## Promotion / Go-port checklist

1. Port `social_post` to AlloyDB with the same natural key; keep `raw`.
2. Implement discover → fetch → synthesize as separate Go stages — the Xano prototypes are #13344 → #13342 → #13343. Discovery semantics to port: handle-reuse guesses (X handle, LinkedIn slug, personal-site domain stem), Exa `includeDomains` search, scrape-verify with first-party bio evidence, two person-binding evidence points for "high", deterministic gate (platform allow-list, twitter.com→x.com canonicalization), record `is_private` and skip the posts lane for private accounts.
3. Port prompt v3 verbatim (system/user split; tier-0 posts evidence; 90-day weighting; interests merge semantics: append-unique, case/whitespace-insensitive, drop empties).
4. Keep provider posture: OpenRouter grok-4.6, strict ZDR (`data_collection: deny`, `zdr: true`, `require_parameters: true`), `sort: throughput`, model as config for A/Bs.

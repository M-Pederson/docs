## What it is

`(User)-[:CONNECTED_ON_ORBITER]->(Person)` — a **declared platform fact**: both parties are Orbiter users who connected in-app. It is binary (exists or doesn't), carries **no weight**, and coexists with KNOWS on the same pair — KNOWS remains the relationship spine whose weight reflects real interaction evidence. Being connected on Orbiter also grants **share-eligibility**: direct note shares (the `RECEIVED` flow) require it.

## When the edge is added

Entry point #3 — both users accept an in-app connection. The write lands in **each user's own graph** (each graph holds its owner's outbound edge, both referencing the same `node_uuid`):

1. Person stub MERGEd if absent.
2. `CONNECTED_ON_ORBITER` edge MERGEd (idempotent).
3. `KNOWS` created **only if absent**, at `origination_source: orbiter_connect` — **strength 50 / weight ≈43** (mutual in-app declaration: stronger than LinkedIn's one-sided 40, well below real interaction at 75). If KNOWS already exists (they emailed before connecting), **its strength is untouched** — the platform edge acts as ranking corroboration (tiebreaker), never a score input.

## Properties

| Property | Value |
|---|---|
| `uuid` | Stable edge id |
| `connected_at` | When the connection was accepted |
| `source` | `"in_app_connect"` |
| `created_at` / `updated_at` | Epoch millis |
| **Weight** | **None** — strength/weight live on KNOWS (this flow initializes strength 50 / weight ≈43 when creating) |

## Simulated example

Mark and Sam Seely connect in-app. Mark's graph (Sam's graph gets the mirror):

```cypher
MERGE (s:Person:Entity {uuid: $sam_uuid})
MERGE (me)-[c:CONNECTED_ON_ORBITER]->(s)
  ON CREATE SET c.uuid = randomUUID(), c.connected_at = $now,
                c.source = "in_app_connect", c.created_at = $now
SET c.updated_at = $now
MERGE (me)-[k:KNOWS]->(s)
  ON CREATE SET k.uuid = randomUUID(),
                k.strength = 50, k.weight = 43,
                k.origination_source = "orbiter_connect",
                k.origination = "Mark connected with Sam Seely on Orbiter on 2026-08-09",
                k.created_at = $now
```

Variant: Mark and Sam had already exchanged 40 emails (`strength: 82 / weight: ≈31`) — the MERGE leaves them untouched; the platform edge adds the CONNECTED badge and breaks ranking ties in Sam's favor.

## mem0 payload — the bootstrap memory is the record

Connecting writes **no additional memory beyond entry point 1's bootstrap** *(confirmed 2026-08-09)* — the contact-creation bootstrap **is** the record of the connection, and its text doubles as the KNOWS edge's `origination` property. Payloads follow the [mem0 writer contract](/guides/open-work/mem0-scope#the-writer-contract-developers-read-this-first): **ledger first** (AlloyDB `extraction_ledger`, `ON CONFLICT DO NOTHING` on the scope hash), then `POST https://api.mem0.ai/v3/memories/add/` with `infer: false` and `run_id = memory_hash`, then stamp `route_status = 'projected'` + `mem0_memory_id`. `timestamp` is **domain time** (when it happened), never ingest time.

```json
POST https://api.mem0.ai/v3/memories/add/
{
  "messages": [{"role": "user", "content": "Mark connected with Sam Seely on Orbiter on 2026-08-09 (source: orbiter_connect)"}],
  "user_id": "user_01KNXVK5MARK",
  "run_id": "e44a7c1b09…",
  "infer": false,
  "timestamp": 1786312800,
  "metadata": {
    "fact_class": "interaction_event",
    "source": "orbiter_connect",
    "contacts_id": 4790,
    "master_person_id": 18455,
    "memory_date": "2026-08-09"
  }
}
```

Sam's side runs the mirror bundle in his own scope. If Sam was already a contact (KNOWS existed), no bootstrap fires — the connect event only adds the platform edge.

## Lifecycle

**Disconnect** removes `CONNECTED_ON_ORBITER` from both graphs and revokes share-eligibility. **KNOWS survives** — the interaction evidence is still real; only the declared fact is withdrawn.

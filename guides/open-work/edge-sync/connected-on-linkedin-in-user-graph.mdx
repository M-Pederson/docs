## What it is

`(User)-[:CONNECTED_ON_LINKEDIN]->(Person)` — a **declared platform fact**: this person is (or was, at import time) a LinkedIn 1st-degree connection of the user. Binary, **no weight**. A LinkedIn connection alone says nothing about relationship strength — the pitch's founding observation — so strength lives exclusively on the KNOWS edge the import creates alongside it.

## When the edge is added — the import trio

Entry point #4 — LinkedIn connections import. **Each imported connection creates all three**:

1. Person stub (`node_uuid` via GET-ADD resolution — profile link is a first-class resolution key).
2. `CONNECTED_ON_LINKEDIN` edge.
3. `KNOWS` at `origination_source: linkedin_import` — **strength 15 / weight ≈55** *(amended 2026-08-09: people connect on LinkedIn without actually knowing each other — initialize near the floor)*. Once real interaction accrues, the nightly scoring pass recomputes strength, and the LinkedIn connection contributes a small **corroboration factor** in the formula; the platform edge itself never changes.

Re-imports are idempotent MERGEs — no duplicates, `updated_at` refreshed.

## Properties

| Property | Value |
|---|---|
| `uuid` | Stable edge id |
| `imported_at` | When this import ran |
| `li_connected_since` | LinkedIn's connect date, when the export provides it (nullable) |
| `source` | `"linkedin_import"` |
| `created_at` / `updated_at` | Epoch millis |
| **Weight** | **None** — strength/weight live on KNOWS (this flow initializes strength 15 / weight ≈55) |

## Simulated example

Mark imports his LinkedIn connections; Priya (a Stripe PM he's never emailed) is among them:

```cypher
MERGE (p:Person:Entity {uuid: $priya_uuid})
MERGE (me)-[c:CONNECTED_ON_LINKEDIN]->(p)
  ON CREATE SET c.uuid = randomUUID(), c.imported_at = $now,
                c.li_connected_since = $li_date, c.source = "linkedin_import",
                c.created_at = $now
SET c.updated_at = $now
MERGE (me)-[k:KNOWS]->(p)
  ON CREATE SET k.uuid = randomUUID(),
                k.strength = 15, k.weight = 55,
                k.origination_source = "linkedin_import",
                k.origination = "Mark imported Priya as a LinkedIn connection on 2026-08-09",
                k.created_at = $now
```

Priya is now an **anchor** (findable in paths, floored in ranking: *"your LinkedIn connection — no interaction history yet"*). Six months later Mark and Priya trade a dozen emails: the nightly scoring pass computes interaction-based strength ≈57, and **the LinkedIn connection now enters the formula as a corroboration factor** (+5, illustrative) → `strength` ≈62, `weight` re-derived ≈38. The platform edge itself is unchanged — it contributes through the scoring formula, never directly to ranking.

## Lifecycle

Imports only add or refresh — removing a LinkedIn connection is not observable from an export, so edges are never auto-deleted. Manual contact deletion removes the trio.

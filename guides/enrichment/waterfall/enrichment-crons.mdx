This page defines which enrichment CRONs must be deployed now and which entity-queue drain CRONs still need to be built.

<Warning>
  **Deployment decision: Only load-bearing CRONs should be deployed now—not entity queue drains.**

  Deploy the control-plane tasks required for a run to terminate or verify successfully. Keep person, company, IMDB entity, and MusicBrainz entity throughput drains inactive. Those drains only change how quickly a backlog moves; the load-bearing tasks below determine whether terminal receipts, parity readbacks, and sandbox wipe verification can ever complete.
</Warning>

## Load-bearing deployment set

The distinction is **control plane versus throughput**. Most queue drains only advance entity backlogs. The following tasks are different: without them, a run can remain pending or verifying forever.

| Task | Data source | Frequency | Why it is required |
| --- | --- | ---: | --- |
| **#192** `sweep-person-non-bio-terminal-retries` | `live` | 60 s | **Critical.** `enrich-master-person` reserves a `person_terminal_stage` receipt before phase 7, but nothing else executes it. Without #192, every person's terminal receipt remains pending forever. |
| **#191** `process-queue-imdb-award-graph` | `live` | 60 s | Required for terminal readback, not throughput. #13194 requires exact relational-table↔graph parity for every award with a `node_uuid`, with no queue tolerance on that branch. #13246 v1.6 reopens the row when a key changes; only #191 services it. |
| **#193 / #195** | `sandbox` | 360 s / 60 s | Sandbox twins of live Tasks #192 and #191. |
| **#194** `process-queue-musicbrainz-sandbox` | `sandbox` | 60 s | Sandbox QA only. It also acts as the wipe certifier; without it, wipes remain stuck at `verifying` forever. |

<Note>
  **Deploy now:** live Tasks **#192 and #191**. Where the sandbox QA environment is deployed, also deploy **#193, #195, and #194**. Task #191 has `queue` in its name, but it is a terminal parity/readback worker—not an entity-throughput drain.
</Note>
